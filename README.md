# DynoLab

A Flutter website for comparing published motorcycle horsepower and torque curves in desktop and mobile browsers. The project contains only the web platform.

[Live App at moto.bendtrailmaps.com](https://moto.bendtrailmaps.com/PcAMeK4EogHwBL8DCw)

## Run

```sh
flutter pub get
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 52741
```

Open http://127.0.0.1:52741. To serve the WebAssembly release build:

```sh
flutter build web --wasm --release --no-web-resources-cdn
./scripts/serve.sh
```

Development used Flutter 3.44.0 / Dart 3.12.0. The original Mac used `/private/tmp/assetcapture-flutter-sdk/bin/flutter`, an isolated recovery copy because `/Users/jeremiah/projects/flutter` was missing its executables. The original SDK was left unchanged. Use a normal complete Flutter installation on a new machine; the temporary path is not a durable dependency. See [toolchain details](docs/development.md#toolchain).

The WebAssembly release includes the JavaScript fallback generated by Flutter for browser compatibility. Fonts, chart images and rendering resources are bundled. No backend, API keys or database are required. Important settings update automatically in the URL, with browser storage as a fallback when no shared state is present.

## Compare curves

- Select a bike family and published stock or upgraded run independently for each comparison; add up to four runs.
- Use **Both**, **Power** or **Torque** to choose visible curves.
- One **Per 100 lb** switch scales **both horsepower and torque** by `100 / total weight`. Units become `hp/100 lb` and `lb-ft/100 lb` together. Torque always uses pound-feet; there is no unit selector. For example, 0.0700 hp/lb displays as 7.00 hp/100 lb.
- Select a model weight preset or enter a custom bike weight. Enable **Rider & gear** to add one shared rider and luggage load to every bike. Rider and gear inputs round to whole pounds and show no decimal places. Each card shows the resulting denominator.
- Hover or touch and drag to inspect all visible curves at a shared RPM. The vertical marker stays at the last position. Focus the chart and use arrow keys to move by 100 RPM.
- Axes automatically cover the selected bikes’ power, torque and RPM ranges, including higher-revving models such as the CBR650R.
- Measurement displays and comparison CSV values use **three significant figures**. Rider/gear inputs intentionally show whole pounds. Calculations and stored values retain their accepted precision. Bike-weight input rounds its display when editing finishes.
- Export selected curves as CSV, including unweighted and normalized values, weight presets, shared load, total weights and provenance.

## Share a comparison

Copy the address bar URL or use **Copy link**. A compact path such as `https://moto.bendtrailmaps.com/AGDCAQ` preserves only the ordered bikes and builds, model weight presets and custom weights, optional shared rider and gear weights, per-100-pound mode, and Both/Power/Torque selection. The comparison count is inferred by reading entries to the end; it is not stored. Presets use permanent numeric IDs and carry no explicit weight. Only custom weights include a weight value. Colors are assigned automatically by comparison position, and torque always uses pound-feet. Colors, units, library search and category, open panels, selected source, visibility, cursor position, scrolling, unfinished weight input, and temporary dropdown menus are excluded from links. Shared links open the comparison and show all included bikes. Library/source navigation and visibility preferences remain local.

A valid shared URL takes precedence over the receiving browser's stored preferences. Weights retain full precision. The binary payload omits defaults and has no version number or checksum. Invalid settings are silently ignored, leaving the saved/default comparison available. Previous query-based link formats are no longer supported. URL updates replace the current history entry, so ordinary adjustments do not fill the Back history. Shared settings are public to anyone with the link; they contain no account information.

## Deploy to Cloudflare

Follow the [full deployment runbook](docs/deployment.md) for authentication, target inspection, release checks, direct path links, DNS/HTTPS, and rollback. The former paused-deployment handoff is obsolete.

`wrangler.jsonc` serves the compiled static assets at **https://moto.bendtrailmaps.com**. The hostname has a Cloudflare-managed DNS record and certificate, plus a hostname-specific HTTP-to-HTTPS redirect that preserves query parameters. Cloudflare manages the domain's DNS and HTTPS certificate through its Worker Custom Domain binding. There is no backend code or database.

```sh
flutter analyze
flutter test
flutter build web --wasm --release --no-web-resources-cdn
npx --yes wrangler@4 deploy
```

Only `build/web` is uploaded. Cloudflare login credentials remain outside the project. An authorized Cloudflare account with access to the `bendtrailmaps.com` zone is required. Local preview links use localhost; public sharing uses the deployed domain. See [compact-link measurements and format notes](docs/compact-sharing.md).

## Dyno library

The searchable library contains **28 families, 76 source records and 56 usable curves**, with **Adventure · 10**, **Dual sport · 10**, **More bikes** and **Upgrades** collections. They are editorial selections spanning different capacities, budgets and riding priorities among U.S.-available model families; they are not sales rankings. Older published test years and historical variants remain explicitly labeled.

Adventure selection: KTM 390 Adventure R, BMW R 1300 GS, BMW F 900 GS, Ducati DesertX, Honda Africa Twin 1100, Suzuki V-Strom 800DE, Yamaha Ténéré 700, KTM 890 Adventure R, Triumph Tiger 900 Rally Pro, Royal Enfield Himalayan 450.

Dual-sport selection: Honda CRF300L, KTM 390 Enduro R, Honda CRF450RL, KTM 350 EXC-F, KTM 500 EXC-F, KTM 690 Enduro R, Husqvarna 701 Enduro family (explicit historical LR test reference), Suzuki DR-Z4S, Suzuki DR650S, Kawasaki KLX300.

The **Requested** filter also includes the CRF250F, CRF300F and CBR650R. The F Hondas are off-road trail bikes and the CBR is a road motorcycle; they are not mislabeled as street-legal dual sports. The 2026 CRF300F has a verified U.S. listing and curb weight but no verified full dyno curve in the reviewed sources, so it remains a source-only record.

The **390 upgrades** filter separates older 373 cc Duke/Adventure tests from the 399 cc / Euro 5b family. Additional research includes an independent stock 2020 Adventure curve and Rottweiler Power Commander V intake/exhaust mapping. BR-Performance Stage 2 and Mantra Stage II document intake/exhaust/tuning combinations but remain source-only without verified primary RPM traces. ECUWEST’s chart is accessible as a source-only record because its speed/RPM mapping and STD hardware header cannot support an unambiguous RPM overlay.

## Data quality

Curves are approximate samples digitized from actual published graphs, with no extrapolation. Original samples are retained in `Configuration.recordedPoints`. For each point, torque implied by recorded horsepower and RPM is averaged with recorded torque. Plotted horsepower is always calculated from that averaged torque and RPM. Between samples, torque is linear and horsepower follows the resulting quadratic curve. Peak horsepower includes interior maxima. Reported publisher peaks remain separate from the reconciled graph values. Different dynos, tires, correction methods, years and accessories prevent a controlled head-to-head comparison.

**CURVE READY** records can be added to the graph. **SOURCE ONLY** records retain hardware evidence, links and notes; peak figures alone are never converted into invented curves. Measurement basis is shown for every record. Weight presets change only mass and do not claim a separate dyno test for each body model.

The original 399 cc KTM chart identifies only the 390 Euro 5b engine family. Its exact tested body model and plotted power scale are uncertain; the app retains its platform-proxy caveat and derives power from its digitized torque. The Honda baseline remains 550 Performance’s CRF300L chart.

The [November 3 family and tune review](docs/tuning-research-2026-11-03.md) documents the search across all 28 families, including missing or rejected evidence. Thirty additional upgrade records include 15 plotted tuned runs; other entries retain peak readings or chart evidence without invented curves. Five additional bikes are the Tuareg 660, KTM 790, KLR650, DR-Z400 and source-only CB500X. Shared families such as KTM 890 have one family selector and multiple model weight presets. Different tested factory calibrations keep their own labeled dyno runs. **Add matching stock run** compares a tune with its own source baseline using the same selected mass.

The [consistency audit](docs/dyno-consistency-audit.md), [per-point CSV](docs/dyno-consistency-points.csv), and [full-precision JSON](docs/dyno-consistency-audit.json) report changes against original values. The audit identifies its dataset size and any changes requiring review; the original 405-point baseline had no changes over the user’s 5% review gate. The app blocks any future reconciliation with a raw torque discrepancy, averaged torque adjustment, or resulting HP adjustment over 5% pending review. Run `dart scripts/audit_dyno.dart` after changing source data.

## Validate and maintain

```sh
flutter analyze
flutter test
flutter build web --wasm --release --no-web-resources-cdn
```

Tests cover torque reconciliation and the review gate, physical consistency between samples, interior horsepower peaks, three-significant-figure formatting, normalization of both metrics, total weights, unit conversion, invalid input, source-only safeguards, ten-pick collection membership, high-RPM domains, search, touch/hover behavior and layouts from 320 to 1440 pixels.

Research expansion JSON and the importer's catalog-family/coverage inputs are the generation sources; the original Honda/KTM arrays remain in `lib/dyno_data.dart`. Run `python3 scripts/import_research.py` after editing reviewed research inputs, then `dart format lib/researched_data.dart` and `dart scripts/audit_dyno.dart`. The [data workflow](docs/data-workflow.md#files-and-generation) lists all inputs and explains validation. `docs/catalog-families.json` defines grouped names, model mass references and legacy aliases. `docs/tune-coverage.json` records a research outcome for every family. Append permanent IDs in `lib/share_catalog.dart` when adding runs or mass presets; never reorder or change existing numeric entries. The generated typed data is bundled in `lib/researched_data.dart`; app state and controls are in `lib/main.dart`, the searchable library in `lib/library_dialog.dart`, and chart rendering in `lib/dyno_chart.dart`.

Run `python3 scripts/verify_sampling.py` to replay the later power-chart ledger against the stored JSON points. It checks 31 curves / 402 points without downloading or changing data; source trace identification still needs visual review. The [maintenance runbook](docs/catalog-maintenance-runbook.md) ties evidence review, generation, sharing compatibility, tests, browser checks and handoff together.
